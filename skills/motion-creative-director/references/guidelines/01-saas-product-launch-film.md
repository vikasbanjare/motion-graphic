# Specialised Guideline 01: SaaS Product Launch Film

A format guide for the flagship film that announces a SaaS product, a major version or a new AI feature. It applies the Master SaaS Motion Design System (Parts 01-11, `research/master/`) to this one format and turns its rules into a plan you can produce. Every number traces to a master section or a reference teardown (`research/videos/`).

## 1. Purpose and audience

**What the film does.** It names the product, shows it doing one job with real UI states, proves value in 1-5 blocks and ends on a lockup with a verb CTA. The story stages are hook → reveal → proof → (benefit) → climax → resolution (P01 §2.2).

**Who watches, and where:**

| Audience | Context | What they need in the first 10 s | Implication |
|---|---|---|---|
| Prospects and buyers (PMs, ops leads, founders, devs) | Website hero, Product Hunt, LinkedIn, X, YouTube | What it is and what it does for *me* | Name by about 2.2-2.4 s (median of the product films); first real UI by 8 s at the latest (6/6 references) (P01 §2.1) |
| Existing users | Changelog, in-app modal, email | What changed, and where the button is | Lead with the new UI state, not the brand |
| Press, investors, the team | Launch post, deck embed | Category, ambition, polish | One hero moment, a clean lockup, the URL that can be read |

**Job of the format:** move people from awareness to consideration. The CTA is "Try [Product] →", "Get early access" or "Join the waitlist", not a hard-sell offer (P01 §2.11 L4).

---

## 2. When to choose this format (and when not)

Choose a **SaaS Product Launch Film** when all of these are true:

1. There is a real product state to show: a UI, an output or a workflow. Proof takes a median **58%** of a launch film (P01 §2.1).
2. There is one positioning line that can close the film (≤6 words).
3. The film is the anchor asset: website hero, launch-day post or keynote opener. Cutdowns come from it (P08 §17.5).

Pick something else when:

| Situation | Better format | Why |
|---|---|---|
| The product is not ready to show (no UI yet) | Teaser / brand sting (5-15 s) | A launch film without real UI breaks the "show first, then label" rule (P01 §2.8) and invites fake mock-ups (P06 UI-R) |
| You must explain an invisible mechanism (security, data pipeline) | VO explainer, template T6/T9 (P01 §2.4) | The mechanism needs narration and 60-120 s |
| One feature, one paid placement | 15 s single-transaction ad, template T3 [V:126cpH] | One use case end to end (P01 TS3) |
| The value is customer outcomes | Testimonial spine T11 | Proof comes from people, not UI |
| Several product lines or use cases | Brand-bookended montage T5 [V:15VhHR] | Needs a montage grammar, not a demo loop |

**Template choice inside this format** (P01 §2.4):

| Product type | Template | Signature |
|---|---|---|
| AI, voice, generation: input becomes output | **T1 Say → See loop** [V:1-6l8S] | Input card → output UI, repeated 3-4 times |
| LLM feature, connector, integration | **T4 Prompt-native** [V:1CSXtQ] | Headline typed as a prompt; UI builds around it |
| B2B ops, payments, data, "unify / automate" | **T2 Claim → Proof alternation** [V:19NRDv] | Dark claim card → light 3D proof, ×4-5 |
| Builder, platform with many outputs | **T5 Brand-bookended montage** [V:15VhHR] | Bookend sentence, slot-machine use cases |

Rule TS1: pick one template and keep it for the whole film (8/8 references).

## 3. Platforms, aspect ratios and length

### 3.1 Deliverables matrix

| Placement | Aspect | Frame | Length | Template column (P01 §2.3) | Notes |
|---|---|---|---|---|---|
| Website hero, YouTube, Product Hunt, keynote | 16:9 | 1920×1080 (3840×2160 flagship) | **60 s** (45-90 s) | 60 s | Master. Website heroes autoplay muted, so the story must work with sound off |
| LinkedIn / X feed | 16:9 or 1:1 / 4:5 | 1080×1080, 1080×1350 | 30-45 s | 30 s / 45 s | Re-layout, not a crop (P02 CO-U18) |
| Reels, Shorts, TikTok | 9:16 | 1080×1920 | 15-30 s | 15 s / 30 s | Text-safe x 120-840, y 270-1210 (P02 §4.7) |
| Paid pre-roll / bumper | 16:9 | 1920×1080 | 6 s or 15 s | PL-05 / PL-15 (P08 §17.4) | Logo plus one claim |
| Changelog / in-app | 16:9 or 4:3 | 1600×1200 or 1920×1080 | 20-30 s, loopable | 30 s without the hook | No music needed; UI only |

### 3.2 Technical delivery (P11 §0.5, P09 §16.11)

| Spec | Value |
|---|---|
| Frame rate | **30 fps native.** Never convert 24/25 → 30 by duplicating frames (judder in [V:15VhHR], [V:1CSXtQ], [V:1Hcg3X]). If generated footage dominates, finish at 24 fps |
| Codec | H.264, yuv420p, BT.709 tagged, **CRF 16-18**, **12-20 Mb/s** at 1080p30 (never below 8) |
| Dither | 1-2% noise on every gradient before the 8-bit encode (banding in 4/8 references) |
| Audio | **−14 LUFS ±1**, **≤ −1 dBTP**, LRA 5-10 LU; AAC-LC 48 kHz 256-320 kb/s; keep WAV 48/24 + stems |
| Captions | Burned-in for social; SRT for YouTube / website |
| Thumbnail | Frame 0 is the thumbnail on feeds: the hook text must be on f0 (P01 H1) |

### 3.3 Length rules

- **Default master: 60 s at 16:9.** 45 s if there are only 3 proof blocks; 90 s only with 5 blocks or a VO (P01 §2.3).
- Over the last three proof blocks each is 10-40 % shorter than the one before, never longer (P08 DU-U3): kivi 14.75 → 11.03 → 6.69 s [V:1-6l8S].
- 9:16 cut: 15-30 s, one use case end to end (P01 TS3), not the 60 s master squeezed.

- 90 s: tagline 2.0 + wordmark 1.2 + symbol or CTA 3.3 + URL 2.0 + fade 0.5-1.5 s [V:1-6l8S t=71.10-77.78s].

## 6. Style direction

### 6.1 Visual concept (P01 §1, P02 §3)

- **2D-first.** All 8 references build on flat layers and a 2D virtual camera. True 3D is a contrast effect: **one hero beat, 10-15% of runtime**, in minimal styles (P10 #1-2; [V:1CSXtQ] 3.67 s of 30 s).
- **One world rule.** Either one light world [V:1-6l8S], [V:1CSXtQ] or a two-world alternation (dark claim / light proof) [V:19NRDv]. Every frame obeys the rule.
- **Frameless UI.** A rounded card without browser chrome in 7/8 references; use a device frame only when the device is the product (P06 #1).
- **Negative space.** ≥85% of a statement frame is empty (P02 defaults).

### 6.2 Colour (P02 §11)

| Token | Default | Rule |
|---|---|---|
| Light canvas | #F5F5F5-#F9FAFC | Off-white, not #FFFFFF, except prompt-native |
| Dark canvas | Hue-tinted near-black (#06004E navy, #0C0A09 warm, #161616 neutral) | Never pure #000 without dither |
| Ink | #0B0B0B-#1A1A1A on light; #F5F7F5-#FCFCFC on dark | ≥4.5:1 always |
| Brand accent | **1 hue**, split into a field tone and a text tone | ≤5% of the frame as a highlight |
| Named colours | ≤5 per film, ≤4 per frame | Real product UI and photos excepted |
| Glow | Emitters and "active" states only; ≤2-3% of cap height on text | 0 in HubSpot; never on body text |

**Palette presets that fit launch films** (contrast computed in P02 §11.13):
- *Airy Aurora* (AI, voice, calm premium): #F9FAFC / ink #0B0B0B (18.85:1) / accent field #8EE1B2, text tone #396454 (6.43:1) [V:1-6l8S].
- *Prompt-native* (LLM features, integrations): #FFFFFF / #1A1A1A (17.40:1) / accent #F65542 on icons only; #CE4737 (4.58:1) if accent text is needed [V:1CSXtQ].
- *Night / Day* (B2B ops, fintech): #06004E ↔ #FCFCFC / accent #F4643C (6.03:1 on navy) [V:19NRDv].
- *Dark neon* (dev tools, asset libraries): #0A0F0A dithered / #F5F7F5 / #38D037 (9.44:1); text on green fills is #161616, never white [V:1ccYWJ].

### 6.3 Typography (P07 §9)

| Role | Size @1080p (16:9) | 9:16 @1920 | Weight | Notes |
|---|---|---|---|---|
| T-STATEMENT | Cap 5.8% H = **90 px font** | 128 px | 400 calm / 500-600 launch | Centred, centre-line y 47-52% H, 35-70% W |
| T-HERO (product name, punch word) | Cap 12% H = **185 px font** | 240 px | 500-700 | Setup : hero ratio 1 : 2.5-3 |
| T-MEGA (climax word) | Cap 31-33% H = 460-510 px font | — | 700+ | Climax only |
| CTA | Cap ≥5% H (≥54 px cap) | ≥52 px body | 500-600 | URL ≥3.5% H |
| Must-read UI text | Cap ≥3% H (≈46 px font); ≥4% H after a cut-in | ≥52 px | UI native | Below 2.5% H = texture only |

- **Families:** 1 sans for everything + at most 1 accent face with exactly one role (8/8 refs).
- **Tracking:** 0 on lines; −1 to −3% on lowercase display; 0 to +3% on display caps. **Leading:** 0.95-1.1 display, 1.4-1.6 UI.
- **Words per read frame ≤6**; a typed prompt may hold 9-10 (P07 #11).
- **Overshoot on type: 0%** (8/8 refs).

## 7. Motion language (with numbers)

Use only the ease tokens from P03 §19.3. Every value below is a frame count at 30 fps.

### 7.1 Ease tokens to use in this format

| Token | cubic-bezier | Use in a launch film |
|---|---|---|
| E-OUT | (0.33, 1, 0.68, 1) | Default entrance: cards, panels, toolbars, words in a line |
| E-SNAP | (0.05, 0.7, 0.1, 1) | Hero-word slam 3-4× → 1×; popovers; oversize labels |
| E-EXIT | (0.3, 0, 0.8, 0.15) | Any move that ends on a cut (shrink, punch, push) |
| E-WHIP | (0.64, 0, 0.78, 0) | Element or camera leaving frame, 6-9 f |
| E-GLIDE | (0.25, 0.1, 0.25, 1) | Cursor travel, trucks, re-centre pans |
| E-INOUT | (0.65, 0, 0.35, 1) | Pull-backs and push-ins that start and end on screen |
| E-SETTLE | (0.45, 0, 0, 1), 45-72 f | Wipes or panels carrying new text |
| E-PUNCH | Exponential scale, +18-33% in 3-8 f | Last frames before a major cut only |
| E-LERP | k = 0.2-0.25 per frame | A line re-centring as words are added |
| E-LINEAR | (0, 0, 1, 1) | Breathing pushes, drifts, counters, crossfades |
| E-CRIT | spring m 1, k 179, c 26.8 | When a spring API is required; 0% overshoot |

**Banned:** Remotion's default `spring()` (16.3% overshoot), After Effects Easy Ease on entrances (26-39% error), and bounce on UI, type, logo or camera (P03 §19.3, P11 AA-T4).

### 7.3 Signature device

Pick **one** signature and use it **3-12 times** (P05 #3). Fewer than 3 uses are not learned; Bumper's grammar used ≈12 times was flagged as monotonous [V:19NRDv]. Good choices for a launch film:
- Punch into the cut, +18-33% over 3-8 f [V:1-6l8S] (4 uses in 78 s).
- Hero-word slam → build → pull-back [V:19NRDv].
- Live-typed line with lerp re-centring (k 0.2-0.25) [V:1-6l8S].
- Brand icon becomes the UI (UI morph 7-13 f) [V:15VhHR].

## 9. Transitions

**Grammar:** ≥70% of scene changes are hard cuts; one signature device; 1 hero one-off transition per 15-20 s (P05 #1-4).

| Budget (P05 §7.5) | 30 s | 45 s | 60 s | 90 s |
|---|---|---|---|---|
| Scene changes | 10-16 | 16-25 | **22-33** | 30-45 |
| Signature device uses | 3-7 | 4-8 | **5-10** | 6-12 |
| Hero one-off transitions | 1-2 | 2-3 | **3** | 3-4 |
| Shape / mask wipes | ≤1 | ≤1 | **≤2** | ≤2 |
| Flash moments | ≤1 | ≤1 | **≤1** | ≤1 |

**Transition specs for this format** (P05 defaults):

| Transition | Spec | Best stage |
|---|---|---|
| Hard cut on the beat | Picture **0-2 f before the beat**, never after | Everywhere |
| Pre-roll into a cut | Last **6-10 f** accelerate (E-EXIT, ×1.3-1.9 per frame) | Every energetic exit |
| Settle out of a cut | 40-64% of travel on frame 1, 86-95% by f3-6 | Every entrance after a cut |
| UI morph (shared element) | **7-13 f**, background refocus 11-12 f | Reveal: icon or headline → UI |
| Interaction-triggered cut | Cut or state change **3-15 f after the click** (median 6-8 f) | Proof |
| Whip into a cut | 6-9 f expo-in, peak 13-20% W/f, blur on the last 2 f | Block to block |

## 10. UI treatment

UI is where a launch film earns trust. Run the five-question test on every UI shot (P06 §8.0): Is it real? Is it readable? Does the action have a visible cause? Is the timing believable? Is there one focus?

### 10.1 Rules

| Rule | Value | Source |
|---|---|---|
| UI source | **Real product UI** (screen capture rebuilt as vector layers, or the design file). Never generated by a video model | P06 UI-R, P11 AA-G9 |
| Hero UI card width | **65-80% W** (16:9); ≈75% W = 810 px (9:16) | P06 #2 |
| Corner radius | 24-32 px @1080p | P06 #3 |
| Card shadow (960-1280 px card) | y ≈24 px, blur ≈48 px, black 6-8%, plus a 1 px hairline at ≈6% | P06 #20 |
| Microinteractions | Real UI speed: label swap 1 f, toggle 3 f, dropdown 6 f (rows 2 f apart), popover 1-2 f | P06 #5 |
| Cursor | Native arrow ≈2% H (≈22 px @1080p); travel **15-20 f** E-GLIDE; dwell **10 f**; press **3 f**; release **6 f** | P06 #9-10, P03 #18 |
| Anticipation before a press | 18-30 f (travel + dwell) | P06 #11 |
| Feedback after a press | State change on the press frame; consequence **3-8 f** later (max 15 f) | P06 #12 |
| Typing to be read | **15-20 chars/s**; key phrase **7-9 chars/s**; filler 28-35 chars/s; phrase pauses 0.9-1.1 s | P03 #19, P07 #18 |
| Caret | Blink 9 f on / 9 f off; lock at 65-66% W once the line passes centre | P07 #19 |
| AI-generation state | Gradient or shimmer **8-15 f**, settles to final colours in 6-8 f | P06 #21 |
| Streaming text | Speech pace 4-7 words/s, each word 30-40% → 100% in 3-4 f; machine pace 1 word per 2 f | P07 #20 |
| Zoom to an element | **Cut-in 2-3.5×**; animate only when the move carries meaning | P06 #16 |
| Dim the context | To 15% (texture) or 50% (secondary) in 3-6 f | P06 #17 |
| Hold on a meaningful state | **≥1.0 s**, and ≥ the text's reading time | P06 #13 |
| Floating callouts around UI | **≤3**, one fact each, 4 f stagger, anchored to what they describe | P06 #23 |
| UI raster resolution | Vector, or ≥ (max zoom × delivery) pixels | P06 #25 |

### 10.2 Choreography patterns to reuse

- **Say → See** (UI-P1) [V:1-6l8S t=17.03-25.47s]: feature name card → input card with live waveform or typed prompt → continuity cut → 8 f empty hold → cascade in reading order (3-4 f stagger) → hold with a slow push → next name card.
- **Text → UI build** (UI-P2) [V:1CSXtQ t=2.13-10.37s]: headline typed on an empty canvas → 0.6 s hold → border and shadow (1-3 f) → brand icon pop (3 f) → toolbar slides up (4-5 f) → pull-back ×0.75 → cursor toggles a source → cut on the riser crest.
- **Brand icon becomes the UI** (UI-P3) [V:15VhHR t=2.5-4.5s]: cursor hovers 1.0 s on the brand mark, clicks, the mark stretches into the prompt pill over 6 f, drop 8 f after the cut.
- **Locked-anchor slot machine** (UI-P4) [V:15VhHR t=8.63-12.83s]: prompt bar fixed to ±1 px while the use case behind it swaps; holds lengthen 21 → 29 → 38 f to land on the hero use case; music sucks out to −35 dB on the send click; result cut 8 f later.
- **Context → extraction → focus** (UI-P5) [V:19NRDv t=16.73-18.2s]: whole table → lift the relevant column → push through.

### 12.3 Claim and payoff lines

- Show first, then label: the UI action comes before the caption that names it (P01 §2.8).
- One accent word per frame, never two (kit recipe rule; P02 accent ≤5%).
- Verbs and outcomes, not adjectives: "Decisions become tasks." beats "Powerful AI meeting assistant."
- Numbers must be verified and sourced. Say them as words in a VO ("seventy-five milliseconds"); show them as digits.
- **Close the loop (L3):** the tagline repeats the hook's line, colour or motif (6/8 refs).

## 14. Building it: motion-kit versus custom, generative video and 3D

### 14.1 What the motion-kit template engine covers

The kit (`motion-kit/`, Remotion 4, 30 fps) builds a film from a JSON spec of scenes. Scene types: `hook, kinetic, orb, title, stat, list, compare, bars, grid, quote, prompt, chat, wave, image, clip, cta, logo`. Themes: `midnight, clean, neon, editorial, pop, desi, corporate, mono, studio, studio-dark`. Formats: `reel` 1080×1920, `portrait` 1080×1350, `square` 1080×1080, `landscape` 1920×1080. The ready-made recipe is `motion-kit/specs/recipes/launch-film-16x9.json` (orb → kinetic → prompt → wave → stat → list → title → cta → logo).

**Theme and motion choice for launch films:**

| Product personality | Theme | `motion` | `transition` | Matches master palette |
|---|---|---|---|---|
| Calm AI, voice, design tools | `studio` (light) / `studio-dark` | `calm` (0% overshoot, blur word-in, 15 f enter) | `auto` or `blur` | Airy Aurora |
| B2B, data, finance, ops | `corporate` or `clean` | `smooth` (0% overshoot, 22 f enter) | `push` / `cut` | Prompt-native, Night/Day |
| Dev tools, gaming, AI infra | `neon` or `midnight` | `snappy` (0% overshoot, 15 f) | `whip` / `cut` | Dark neon |
| Editorial brand frame | `editorial` or `mono` | `smooth` | `fade` / `cut` | Editorial frame |

Avoid `motion: "bouncy"` for any launch film: it adds spring overshoot, and the master requires 0% on type, UI and logos.

**Storyboard → kit mapping (Brieflow):**

| Storyboard beat | Kit scene | Kit fields | Fidelity |
|---|---|---|---|
| #1-2 hook "Still taking notes?" | `kinetic` (or `hook` with `strike`) | `lines: ["Still taking *notes*?"]` | Good. No live caret or lerp re-centre; the punch-into-cut is approximated by `transition: "zoom"` |
| #3 pain | `title` with `bg: "inverse"` or `image` (illustrated call plate, `move: "in"`) | `headline: "Decisions get lost."` | Partial. No falling notes or UI morph |
| #4 reveal | `orb` or `logo` | `headline: "Meet *Brieflow*."` | Good for a calm reveal; no stroke → fill logo build |

**Workflow** (from `skills/motion-director/references/production.md`): `npm run check -- specs/brieflow.json` → `npm run qa` → `npm run brand -- <logo> --spec specs/brieflow.json` → `npm run music -- specs/brieflow.json --track music/launch-100bpm.mp3` (snaps cuts to beats, writes `audio.beats`) → `npm run make -- specs/brieflow.json --crf 18`. For the vertical cut, change `format` to `reel` and trim to 5-7 scenes (≤30 s).

**Known kit gaps for this format** (build these outside the kit and bring them in as `clip`):
1. Real UI choreography: cursor paths, result cascades, dropdowns, locked-anchor swaps (P06 UI-P1 to P5).
2. Punch into the cut, hero-word slam at 3-4×, lerp re-centring of a live-typed line.
3. 3D: tilted UI planes, screen-to-world pull-back, push-through, stepped orbit, particle transfer.
4. Logo build (stroke → fill → sheen) and a converging lockup with a 4 s still.
5. Frame-exact SFX at the press frame or peak velocity (the kit places SFX per scene, not per event).

### 14.2 Custom Remotion or After Effects (deterministic, for all UI and type)

Rules from P11 AA-T: drive every value from the frame number; clamp every `interpolate`; ease tokens only (`Easing.bezier(0.33, 1, 0.68, 1)` and the rest of §7.1); `spring` only as E-CRIT (stiffness 179, damping 26.8) or damping 200; scale in log space for zooms; fonts loaded with explicit weights before measuring; one string table; cue sheet generated from the scene event list; ProRes 4444 (`yuva444p10le`) for transparent overlays.

### 14.3 What needs generative video (Flow / Veo / Sora / Runway / Kling / Higgsfield)

Use generation **only for things allowed to vary** (P11 §21.1): ambient life plates, abstract backgrounds, textures and B-roll of people working (faces not identifiable or cast with consent). Never for the UI, the logo, type, numbers, the product or a real person (AA-G9).

| Launch-film need | Generate? | How |
|---|---|---|
| Blurred "life" plate behind a UI card (office, call, desk) | Yes | One slow move ≤0.2% W/f; defocus in compositing; B&W → colour bloom in compositing [V:1-6l8S] |
| Aurora or gradient field | Prefer code (shader or gradient) | Deterministic and loopable; generate only for organic textures |
| Hero abstract object (orb, glass form) | Possible | Clean background, one camera move; composite type later |
| UI, dashboard, screen content | **No** | Real UI as vector layers |
| Logo, wordmark, any text | **No** | Composite |
| The 3D data transfer | **No** (precision needed) | 3D or Remotion/three.js |

Operating rules (P11 AA-G): Veo 3.1 clips are 4, 6 or 8 s at 24 fps; generate 1.5-2 s longer than the edit length and use the middle; one named camera move per clip with start and end framing; prompt order Cinematography → Subject → Action → Context → Style, with the continuity block (palette hex, key-light direction, lens, grade, grain) repeated verbatim; negative prompt "text, subtitles, captions, letters, watermark, logo, numbers, signage, screen content, user interface"; ≤3 reference images and a fixed seed per look; 2-4 takes per shot, keep the one that passes QC; mute generated audio; upscale before compositing; grade every plate together; keep a generation log. If generated plates dominate, finish at 24 fps; otherwise conform carefully and never pad to 30 fps by duplicating frames.

**Example plate prompt (Veo / Flow):** "Slow push-in, 35 mm, from medium-wide to medium over 6 seconds, roll 0°. A bright modern meeting room with a laptop on a pale oak table, nobody in frame. Morning daylight from the top left. Large clean empty wall in the upper half for graphics. Soft, airy, low contrast, off-white #F9FAFC highlights, cool violet shadows #C7D2FE, fine grain 1%." Negative: "text, letters, logo, screen content, user interface, people's faces, hands, lens flare".

### 14.4 What needs 3D

| Shot | Why 3D | Spec |
|---|---|---|
| Screen-to-world pull-back + dolly (#9) | Real parallax and DOF sell "data moves between systems" | ×0.32 in ≈1 s, then ×2.2 dolly in 15 f; 200-300 particles made from the card's colours; 3 planes; one key light matching the 2D shadows |
| Stepped orbit of integration tiles (#15) | Rotation around a hub | 9-12 f per step, steps 1.2 s apart; text faces camera on the focal plane |
| Tilted proof tables (T2 style) | Kinetic × 3D look | ≤15° while read; 30-45° only in transit; 180° motion blur |

Tools: Remotion + three.js (`@remotion/three`) when the 3D is UI planes; Blender or Cinema 4D for materials and lighting; the Higgsfield 3D scene builder for blockouts. 3D is a contrast effect: one hero beat, 10-15% of runtime, in minimal styles (P10 #2). Hand off between 2D and 3D only through a motivated move (tilt onto a plane, screen-to-world pull-back), never a crossfade (P10 #24).

## 15. QC checklist for this format

Run per shot (Gate 1), on the locked cut (Gate 2) and on the final MP4 (Gate 3) (P11 §22). Severity: **S1** blocks release; **S2** must be fixed or signed off.

**Story and copy**
- [ ] Hook text on f0, first change by f3; hook 1.2-2.4 s and ≤7 words (S1).
- [ ] Product name by 2.4 s (or ≤5 s after a deliberate pain setup); first real UI by 8 s (S2).
- [ ] One template, one demo grammar, repeated in every proof block (S2).
- [ ] Every claim and number verified and sourced; no lorem ipsum; strings match 100% across shots and cutdowns (S1).
- [ ] Hook line or motif returns in the tagline or lockup (S2).
- [ ] CTA = verb + destination, cap ≥5% H; URL ≥3.5% H (S1 for performance cuts).

**Timing and rhythm**
- [ ] ASL 1.8-3.0 s; no more than 1.5 s without a discrete event, except a designed still (S2).
- [ ] ≤3 same-treatment text cards in a row; a reveal grammar used ≤6 times before it varies (S2).
- [ ] Payoffs and UI states held still ≥1.0 s; statement lines ≥0.3 s per word (S2).
- [ ] Final lockup still ≥1.5 s (2.2 s premium; ≥4 s with a QR) (S1).
- [ ] Music-led: ≥60% of hard cuts 0-2 f before a beat; none after (S2).
- [ ] Drop lands 0-8 f after the first product frame (S2).

**UI and type**
- [ ] UI is real (captured or from the design file), not generated or invented (S1).
- [ ] Must-read text cap ≥3% H at 16:9 (≥52 px at 9:16); nothing that carries meaning below 2.5% H (S2).
- [ ] Every click has a visible cause and a consequence 3-8 f later (S2).
- [ ] Typing to be read at 15-20 chars/s; key phrase 7-9 chars/s (S2).
- [ ] 0% overshoot on type, UI chrome, logo and camera (S2).
- [ ] One primary motion at a time (S2).
- [ ] Text-safe: 16:9 x 96-1824, y 54-1026, with CTA above y ≈918; 9:16 x 120-840, y 270-1210 (S1 for clipped text).
- [ ] Contrast ≥4.5:1 (3:1 only for large text; 7:1 over footage) (S1).

**Look and motion**
- [ ] One accent hue ≤5% of the frame; ≤5 named colours (S2).
- [ ] One key-light direction for every 2D shadow, 3D light and plate (S2).
- [ ] Nothing moves faster than 5% W/f unblurred (S2).
- [ ] At most 1 flash moment, ≤3 f per colour, ≤3 flashes per second (S1, photosensitivity).
- [ ] No 1-frame artefacts at cuts: step every cut ±10 f at 1-frame steps (S1).
- [ ] Generated plates: no glyphs, no UI, no faces, no boiling textures; the continuity block was used (S1).

**Sound**
- [ ] −14 LUFS ±1 and ≤ −1 dBTP, measured on the final MP4 (S1 for overs).
- [ ] Clicks on the press frame; whooshes ≤2 per film, peaking on the fastest frame (S2).
- [ ] Hit on the lockup ±2 f; music ends with or after the last frame (S1).
- [ ] The film works muted: the story is readable from the picture alone (S2; website heroes autoplay muted).

**Delivery**
- [ ] 1920×1080 or larger, 30 fps native, 0 duplicated frames in any move (S2).
- [ ] H.264 CRF 16-18, 12-20 Mb/s, yuv420p, BT.709 tagged; 1-2% dither on gradients (S2).
- [ ] Captions burned in for social; SRT for YouTube and website (S2).
- [ ] 9:16 and 1:1 versions are re-layouts, not crops (S2).

## 16. Common mistakes in launch films (and fixes)

| # | Mistake | Seen in | Fix |
|---|---|---|---|
| 1 | Meaning carried by UI text too small for a phone | 7/8 refs (kivi UI 1.2-2% H, Bumper ≈1% H) | Cut in 2-3.5× on the one value; caption it at ≥3% H cap |
| 2 | Delivered below 1080p, at a low bit rate, or with frame-rate judder | 8/8 as received; Wix ≈652 kb/s; 25 → 30 fps duplicates in 3/8 | Render natively at 1080p30+, CRF 16-18, 12-20 Mb/s |
| 3 | Weak ending: bare URL, no lockup, music gone before the picture | kivi, Chowdeck, Lottieicon (music ended 3.7 s early), Solar | Tagline → lockup → CTA, still ≥2.2 s, sting on the lockup |
| 4 | Text-card fatigue: one reveal grammar over and over | kivi 5 text cards in a row; Lottieicon 6 in a row; Bumper ≈12 uses of one grammar | ≤3 cards in a row; vary between build, slam and type-on; put proof between claims |
| 5 | Payoff not held long enough to read | Solar ≈0.4 s; Chowdeck "Order delivered" 2 f | Hold ≥1.0 s still, plus reading time |
| 6 | Mid-film energy dip | kivi 22-31 s; Bumper's 6.3 s network shot | An in-shot event every 0.8-1.5 s; make the breather musical (breakdown), not empty |
| 7 | Loudness off target | kivi −10.7 LUFS; NOSTRA −7.9 LUFS / +1.6 dBTP; Lottieicon −16.6 LUFS | Master to −14 LUFS ±1, ≤ −1 dBTP |
| 8 | Static or slow first frame | Chowdeck static for 0.73 s | Hook on f0, motion by f3 |
| 9 | 1-frame artefacts at cuts | kivi light-leak patch and overlapping word; Bumper dip to black | Step every cut frame by frame |
| 10 | Inconsistent plates or light | kivi's three illustration styles; Solar's two light directions; Bumper's one stock photo | One plate style, one key light, one grade |
| 11 | Mock UI that does not match the product, or UI generated by AI | Teardown QC flags (P06 UI-R) | Use real UI states; never generate UI |
| 12 | Bounce and overshoot on type or UI (default springs) | Kit `bouncy`; Remotion default spring (16.3%) | E-OUT / E-CRIT; `motion: "calm"` or `"smooth"` in the kit |
| 13 | Text clipped by the frame or by platform UI | Bumper caption clipped for 5 s; Chowdeck lower UI band below the 9:16 safe line | Safe areas per format; re-lay out 9:16 |
| 14 | 3D everywhere | (Context-dependent; minimal films use one beat) | One hero 3D beat, 10-15% of runtime |
| 15 | Montage with no stated claim | NOSTRA feature parade; Wix ice-bottle montage | Label every montage with one claim before or after it |
| 16 | Copy inconsistencies across a cut | Wix "make" vs "create"; Lottieicon "4,863+" vs "50 + Categories" | One string table for every scene and cutdown |
