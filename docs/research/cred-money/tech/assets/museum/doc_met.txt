### Latest Updates

September 4, 2026

A new paginated search endpoint is available at

```
/public/collection/v1.1/search
```

. It accepts the same filters as the existing search endpoint and adds two parameters for paging through results:

* offset: the zero-based index of the first result to return (default 0).
* limit: the number of results to return per page (default 100, maximum 500).

The existing

```
/public/collection/v1/search
```

endpoint is deprecated and will be retired on October 1, 2026. Until then it is unchanged: it still returns every matching Object ID in a single response. Please migrate to

```
/v1.1
```

before that date, and see Migrating from /v1/search for what changes and what to do if you rely on retrieving every matching Object ID in one request. To retrieve a full list of Object IDs (for example, every object with an image), use the

```
/objects
```

endpoint or the Open Access dataset.

## The Metropolitan Museum of Art Collection API

The Metropolitan Museum of Art presents over 5,000 years of art from around the world for everyone to experience and enjoy. The Museum lives in two iconic sites in New York City—The Met Fifth Avenue and The Met Cloisters. Millions of people also take part in The Met experience online.

Since it was founded in 1870, The Met has always aspired to be more than a treasury of rare and beautiful objects. Every day, art comes alive in the Museum’s galleries and through its exhibitions and events, revealing both new ideas and unexpected connections across time and across cultures.

The Metropolitan Museum of Art provides select datasets of information on more than 470,000 artworks in its Collection for unrestricted commercial and noncommercial use. To the extent possible under law, The Metropolitan Museum of Art has waived all copyright and related or neighboring rights to this dataset using the Creative Commons Zero license. This work is published from the United States of America. These select datasets are now available for use in any media without permission or fee; they also include identifying data for artworks under copyright. The datasets support the search, use, and interaction with the Museum’s collection.

The Met’s Open Access datasets are available through our API. The API (RESTful web service in JSON format) gives access to all of The Met’s Open Access data and to corresponding high resolution images (JPEG format) that are in the public domain.

## Access to the API

At this time, we do not require API users to register or obtain an API key to use the service. Please limit request rate to 80 requests per second.

## Endpoints

There are API endpoints available for the following elements:

* Objects: A listing of all valid Object IDs available for access.
* Object: A record for an object, containing all open access data about that object, including its image (if the image is available under Open Access)
* Departments: A listing of all valid departments, with their department ID and the department display name
* Search: A listing of all Object IDs for objects that contain the search query within the object’s data

## Migrating from /v1/search

```
/public/collection/v1/search
```

will be retired on October 1, 2026. Requests after that date
will no longer be served. This section covers what to change.

### If you page through results or only need the top matches

Switch the path from

```
/v1/search
```

to

```
/v1.1/search
```

and keep your existing query string. Every
filter parameter is accepted unchanged (

```
q
```

,

```
isHighlight
```

,

```
title
```

,

```
tags
```

,

```
departmentId
```

,

```
isOnView
```

,

```
artistOrCulture
```

,

```
medium
```

,

```
hasImages
```

,

```
geoLocation
```

,

```
dateBegin
```

/

```
dateEnd
```

), and
the response keeps the same

```
{ total, objectIDs }
```

shape.

The one behavior change to plan for:

```
/v1.1
```

returns the first 100 Object IDs by default, not the
entire result set.

```
total
```

still reports the full number of matches, so use it to drive paging
with

```
offset
```

and

```
limit
```

.

### If you rely on receiving every matching Object ID in one response

This is the case that needs the most attention, and it is common for requests like

```
?hasImages=true
```

.

```
/v1.1
```

cannot return an unbounded result set:

```
offset
```

+

```
limit
```

may not exceed
10,000, so only the first 10,000 results of any query are reachable through search. Choose one of:

* The Open Access dataset is the best option for bulk work. It is a CSV of the entire open-access collection, updated regularly, and needs no API requests at all.
* ```
  /public/collection/v1/objects
  ```

  returns every valid Object ID in the collection and accepts

  ```
  metadataDate
  ```

  and

  ```
  departmentIds
  ```

  . Use it when you want the full ID list rather than a filtered search.
* Page through

  ```
  /v1.1/search
  ```

  with

  ```
  offset
  ```

  /

  ```
  limit
  ```

  when your query matches fewer than 10,000 objects.

### Other differences worth knowing

* ```
  /v1.1
  ```

  does not require

  ```
  q
  ```

  . Filter-only requests such as

  ```
  /v1.1/search?hasImages=true&departmentId=11
  ```

  work as expected. On

  ```
  /v1
  ```

  , a request with filters but no

  ```
  q
  ```

  parameter returns an error.
* Result counts and ordering differ between the two endpoints.

  ```
  /v1.1
  ```

  runs on a different search backend, so for the same query the set of matches and their relevance order will not be identical to

  ```
  /v1
  ```

  . Expect broadly similar but not equal results, particularly for artist-name queries. Compare on your own queries before cutting over.
* ```
  total
  ```

  is exact on both endpoints, so it remains safe to use for paging arithmetic and for displaying a result count.

### Questions

If none of the options above fit your use case, please open an issue on the Open Access repository and describe what you are building so we can advise before October 1, 2026.
